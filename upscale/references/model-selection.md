# 模型选择

## 固定快捷档

本 skill 预置三档操作约定：

| 档位 | 模型 ID | 主要用途 |
| --- | --- | --- |
| 最快方案 | `realcugan-pro-x2` | 用户明确要求最快、速度优先或快速方案 |
| 标准方案 | `realesrgan-x2plus` | 用户要求标准、均衡，或未给出任何选择偏好 |
| 高质量方案 | `seedvr2-3b` | 用户明确要求高质量或质量优先，并能接受生成式细节变化 |

用户直接给出模型 ID 或 API 广告的模型名称时，精确选择优先于快捷档。快捷档模型仍须通过本次 `/api/capabilities` 校验；不可用时不静默回退。

## 基于实时能力进一步建议

每次从 `/api/capabilities` 读取 `models`、`selection_profiles` 和当前基线。三档名称是工作流入口，不是脱离素材、模型版本和实测条件的普遍排名。

- 先按 `models.<id>.media_types` 过滤当前图片或视频。
- 用户未指定模型和档位时，使用标准方案 `realesrgan-x2plus`，而不是直接沿用 `submission_defaults.<media_type>`。
- 用户指定模型时，确认它存在且支持当前媒体类型；若能力返回 `recommendation.avoid_for` 或 `cautions`，在与用户用途冲突时先说明风险，但不要擅自改选。
- Logo、角色、小图案或文字一致性重要时，谨慎使用会生成新细节的模型。
- 动漫、真人、降噪、速度优先等请求可参考 `selection_profiles` 的候选顺序，但历史 benchmark 不是当前 GPU 空闲、权重可用或时限承诺。
- 图片倍率仍受 API 的输入/输出像素、边长和模型原生倍率约束；高于模型原生倍率的部分可能只是插值。

给出建议时至少包含：推荐模型、适用原因、主要风险，以及一项有意义的替代方案。只有 API 返回了对应实测数据时才引用速度、显存或质量数值，并附上基线条件；不要从模型名推断未提供的性能。

健康检查、能力元数据和 benchmark 只能证明合同与历史基线；只有任务完成并下载验证结果，才证明本次超分成功。

## 补帧模型

- 默认选择 `rife-v4.25`，用于一般真人、动画和游戏视频。
- `rife-v4.25-lite` 可作为较低显存候选，但必须用业务片段验证吞吐量。hc88的20秒人物样本中，它少占约0.12 GiB补帧显存，却没有比标准版更快。
- 两者都使用切镜启发式保护；快速遮挡、闪光、字幕和大幅运动需人工查看，不能把启发式处理描述为完整镜头检测。
