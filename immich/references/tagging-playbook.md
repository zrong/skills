# 批量视觉打标 Playbook

通过视觉理解给资产打中文 tag、标记无价值内容为「建议删除」、补充描述。
配套 CLI：`immich tag-fetch` / `immich tags-ensure` / `immich tag-apply` /
`immich tag-verify`（见 SKILL.md §10）。

## 总体策略：两条流

按"素材怎么进的库"分两条流水线，规模决定打法：

| 流 | 适用 | 方式 | 实测规模 |
|---|---|---|---|
| A 逐资产 | 日常上传（截图/手机照/AI视频/单据），量 ≤ 数千 | 每张缩略图都看，逐个决策 | 2325 个/半天 |
| B 按簇 | 大批量导入的整理库（按文件夹组织），量上万 | 每个文件夹簇采样 2-5 张视觉确认后整簇打 tag | 21000 个/2 小时 |

外部库资产在只读挂载下元数据写入会被静默回滚（见
`api-pitfalls-and-debugging.md` §10），开打前先确认 sidecar 可写。

## A/B 通用流程

1. **建 tag 字典**（幂等，已有同名 tag 直接复用）：
   ```bash
   uv run --project {SCRIPTS_DIR} immich tags-ensure \
     --names "截图,聊天记录,AI生成,表情包,美食,旅行,家庭,生活记录,医疗健康,证件资料,用车,工作,影视动漫,教程资料,建议删除" \
     --colors "#1971c2,#1098ad,#ae3ec9,#f59f00,#e8590c,#2f9e44,#e64980,#74b816,#0c8599,#f08c00,#495057,#4c6ef5,#6741d9,#868e96,#e03131" \
     --map-out tag_map.json
   ```
   字典按需增删，但一次会话内固定；名字用中文短词。
2. **枚举资产**：`POST /api/search/metadata` 分页拉全量，**客户端过滤**
   `createdAt`（记录创建时间=上传/扫描时间）——注意该接口忽略 pageSize
   （恒 250/页）、`total` 是页内计数、默认排序不是 createdAt（见 §9）。
3. **切批次/簇**：
   - A 流：按 createdAt 倒序切成 ≤60 个/批（用户要求"从新往旧"时尤其重要）
   - B 流：按目录路径前缀聚簇（路径段要数对：`/mnt/album/<一级>/<二级>`
     是 split 后的 `[:5]`），<20 个的小簇并入父级；每簇随机采样
     2-5 个（≥100 个的簇取 5）
4. **下载缩略图**：
   ```bash
   uv run --project {SCRIPTS_DIR} immich tag-fetch batch_A_00.json thumbs/A_00
   ```
   默认 thumbnail 档（≈250px）够分类；需要读截图文字时对单个资产用
   preview 档重取。`_failed.txt` 里的资产跳过打标、单独汇报。
5. **逐张/逐簇决策**（用 Read 工具看图，文件名只作辅助）：
   - A 流每张产出 `{"id", "tags": [...], "description": null|"<≤60字>"}`
   - B 流每簇产出 `{"dir", "tags": [...], "memberIds": [...], "note"}`，
     memberIds 原样复制簇清单；样本与目录名不符就追加采样，仍不符在
     note 里记录
6. **幂等应用**：
   ```bash
   uv run --project {SCRIPTS_DIR} immich tag-apply decisions/A_00.decisions.json
   ```
   tag 分块 PUT 并逐条校验响应；`already=duplicate` 计数为幂等成功；
   description 仅在当前为空时写（绝不覆盖下载视频的原始文案等已有内容）。
7. **收尾必跑全量 diff**：
   ```bash
   uv run --project {SCRIPTS_DIR} immich tag-verify decisions/A_00.decisions.json
   ```
   并发写入会静默丢 ~7% 赋值、只读挂载会整体回滚——抽查不足以兜底，
   A 流收尾对全部批次、B 流对全部簇跑一次全量 verify（exit 1 = 有缺失），
   对缺失项重放 tag-apply 直到归零。

## 子代理派发经验（大规模时）

- 单代理一批 ≤60 个资产（缩略图+决策写入），一轮并发 **3 个**（实测
  账号并发上限），每批 6-12 分钟
- 代理提示词自包含：指到 playbook 文件 + 批次文件 + 输出 decisions
  路径，要求"每个资产必须看图决策、decisions 覆盖全部 id"
- 缩略图文件名 `<序号>_<id前8>.jpg`，用 id 前 8 位映射回资产
- B 流簇组文件每份 ≤8 簇，samples 拼成临时清单走 tag-fetch

## Tag 判定基准（可按库调整）

| tag | 判定 |
|-----|------|
| 截图 / 聊天记录 | 屏幕截图；其中聊天界面另加聊天记录 |
| AI生成 | AIGC 图/视频（画面"内容由AI生成"声明、AI 水印、AI 账号生态） |
| 表情包 / 美食 / 旅行 / 家庭 / 生活记录 | 常规内容分类 |
| 医疗健康 / 证件资料 / 用车 / 工作 | 报告单据、证照票据、车辆、行业活动 |
| 影视动漫 | 观看中的影视/动漫/短剧 |
| 教程资料 | 有回查价值的教程/笔记/信息截图 |
| 建议删除 | 瞬时价值：播放界面截图与录屏、小游戏广告、验证码/临时二维码、过期促销、误拍废片、纯黑视频、重复状态截图 |

「建议删除」从严：家庭照片、医疗单据、证件票据、用车故障、工作素材
**即使画质差也不打**；外部家庭库只允许整簇空白/损坏帧时打。一个资产
最多 3 个 tag（内容 tag + 建议删除可叠加）。

## 描述规则（仅 A 流）

- 只写 `desc` 为空的资产；已有描述（如下载视频的原始文案）一律不动
- 值得写的：医疗报告（项目/医院）、证件（名称）、银行支付（用途）、
  车辆故障（现象）、活动照片（会议名）等回查场景
- 中文 ≤60 字，直接陈述，不加"这是一张…"前缀

## 特殊情形

- **MVIMG/动态照片视频部分**：服务端常无缩略图（404），按同名 JPG
  静帧的 tag 补齐（文件名同 stem），信息无损失
- **归档/回收站资产**：不在共享范围（合作伙伴看不到），打不打 tag 由
  库管理策略决定，默认跳过
- **B 流描述**：簇级不写描述（目录名已是语义），个别样本反例记 note
  交人工判断
